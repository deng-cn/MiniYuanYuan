## 来源

- **1101 线**：`1101_新主题_全api产出`，14 个分片，按正文字数占训练集 **61.1%**（170,831,643 字）；
- **1123 线**：`1123_全api产出`，C01–C10 共 10 个分片，占 **38.9%**（108,981,646 字）；
- 全部由 API 批量生成 + 规则构造，再统一清洗成对话格式。没有人肉标注，也没有从网上抓的文本。

## 格式

一行一条样本，UTF-8，字段固定两个：

```json
{"id": "1123-C05-000123", "turns": [{"role": "user", "text": "..."}, {"role": "assistant", "text": "..."}]}
```

`role` 只有 `user` / `assistant`，多轮就是多个 turn 依次排。带资料的任务（RAG 定位、总结）把资料放在**第一个 user turn**，问题放第二个，推理时对应 `<user>{资料}<sep><user>{问题}<sep><assistant>`。

## 去重说明

`C10_文字改写与语言任务` 曾在两条产线里各出一份，正文完全相同、只有 `id` 前缀不同。
仓库只保留 `raw/` 里那份（真正进过训练的那份），`new/` 下不再重复收录。

## 已知质量问题

这批数据是为了让 30M 模型学会「中文对话长什么样」，不是知识库：

- 模板化明显：同一问答骨架换个名词就是一条新样本，`C04 实物属性` 尤其重；
- 同义重复多：`1101 基础知识型问答` 90 万行里有大量近义改写；
- 事实密度低且不保证正确：冷门数值、日期、人名容易串台，模型也学了这个毛病；
- 长尾极不均匀：`现代生活制度` 只有 111 行，`物理化学` 447 行。

要用它训更强的模型，建议：按线做温度采样而不是按行随机、把 `定位/总结` 类长样本单独加权、对 `C04` 做语义去重。

## 解压与打包

```bash
# 解压（Linux / macOS / Git Bash 均可）
for f in corpus/raw/*.jsonl.xz; do xz -dk "$f"; done

# 打包成训练用的 bin（1088 上下文，自带 train/val 切分）
python tools/data.py --src corpus/raw/*.jsonl --out dataset/full --max-len 1088
```

打包后 `dataset/full/` 会有 `train.bin` / `train_lbl.bin` / `val.bin` / `val_lbl.bin` 与 `meta.json`（2.21M 行 → 27.2 万窗口 / 2.96 亿 token）。
这几个 bin 单文件 565 MB，超过 GitHub 的 100 MiB 限制，所以仓库只放压缩语料，不放 bin。
