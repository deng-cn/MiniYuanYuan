# 语料产出流程、提示词样例与待补全清单（1123 产线）

> 本文说明本仓库 `1123` 线语料（`corpus/raw/1123__*` 与 `corpus/new/*`）的设计思路、自动化生产流程、典型提示词长什么样，以及**目前已经产出了哪些、还差哪些没产出（估算成本约 ¥50）**。
>
> **安全说明**：本仓库不包含任何 API 密钥、私钥或账号凭证。如需自行复现或帮着补全剩余分片，请自备大模型 API Key（本产线实测使用小米 `mimo-v2.6-flash` 半价 Batch API，在本地环境变量配置 `MIMO_KEY` 即可）。

## 一、整体产出流程（四步流水线）

小模型（20M～30M）吃不下杂乱的网页爬虫，因此 `1123` 线完全采用**“受控词表 + 结构化母表 + 正交组合配方 + 强规则门禁”**的合成路线，核心流程如下：

```text
[1. L0 结构化母表底座]
   3,196 核心一级词 × 10 张母表（形容词/世界树/物理现象/实物五层属性/生活常识/社会角色/故事种子/8,181 交叉边）
        │
        ▼
[2. 正交多维切片调度器]
   13 大类 / 84 小类 / 307 主切片 + SG 14 故事泛化切片
   每小类拆成 f1(基础主轨) / f2(进阶多维) / fb(负样本与纠偏，全库约 33%)
        │
        ▼
[3. 半价 Batch API 批量生成]
   模型：mimo-v2.6-flash（关闭思考模式 thinking=disabled）
   写法：固定 SYSTEM 前缀（吃 Prompt 缓存） + Python 随机抽签拼接的可变 USER 配方
   单包 ≤ 18,000 条请求，非纯文章轨统一 JSON 结构化输出
        │
        ▼
[4. 三层确定性脚本门禁 + 去重入库]
   JSON 修复解包 → SampleGate 全局红线检查 → 切片专属 verify_fn 硬验 → sample_id/内容指纹去重
   全库实测门禁通过率 98.67%（728,880 / 738,670），不达标样本全部拦截淘汰
```

### 几个关键设计原则
1. **防同质化**：不让弱模型自己瞎编题材，而是用 Python 调度器从母表里随机抽签组合 `(人物, 场所, 天气, 物品, 冲突骨架, 叙事结构, 结局走向)`，强制 3,196 个核心词跨界交织（多词交叉率 > 74%）。
2. **高比例负样本（约 33%）**：专门设计了三大类负样本，防止小模型满嘴胡编：
   - **错答纠偏（`fb-C / ANS-FIX`）**：首轮故意漏元素或答错（首轮不计 Loss），用户指出后第 2 轮简短认错并给出正确重写（仅终轮计 Loss）；
   - **未提拒编（`fb-B`）**：在带资料问答或故事反问里故意追问文中压根没写过的细节，训练模型老实说“文中没提到，没法确定”；
   - **缺条件澄清 & 边界拒答（`fb-A`）**：题目缺关键前提（如缺单位、缺总数、需求太模糊）先友好反问澄清；超出纯文本能力（联网查实时天气、设闹钟、跨会话记忆）明确拒绝并给替代建议。
3. **纯文章/故事第三人称硬锁**：所有纯文章与故事叙述正文严禁出现第一人称“我/我们/咱们”（仅允许人物对话弯引号 `“”` 内自然出现），避免小模型在非对话语料里学乱人称。
4. **三层确定性脚本门禁**：不靠肉眼抽检，每条产出都过代码校验——自动拦截 AI 味客套话（“希望对你有帮助”等）、内部标签泄露、越过原文脑补数字、违规承诺联网查资料、第一人称叙述、必含元素漏写、以及验证集防泄漏。

## 二、提示词大概长什么样子（脱敏样例）

实际生产时，每个切片有一段**固定 `SYSTEM` 提示词**（约束格式、字数、防破损、第三人称等铁律）和一条**程序动态拼装的 `USER` 配方**。下面放 4 类最有代表性的简化示例：

### 样例 1：带资料 3～7 轮精准定位 + 未提拒答（`C07-01`）
- **SYSTEM（固定前缀）**：
  > 你在生成「自备客观资料 + 3～7 轮深度定位与拒答」对话。先在 `passage` 字段写一段 180～280 字信息充实的客观说明资料（含 4～6 个清晰事实点），再在 `turns` 里按指定轮数写连续问答：逐轮紧扣原文不同细节精准定位，并穿插 1～2 轮原文压根没提过的细节追问，AI 必须老实说明文中未提及、绝不脑补数字。中文正文引号一律用中文弯引号 `“”`，严格输出 JSON：`{"passage":"...","turns":[{"u":"...","a":"..."}]}`。
- **USER（Python 配方拼接）**：
  > 主题一级词：「陶罐」（类别：日用器皿）  
  > 指定资料切面：材质特性与日常保养；自然融进关联词「蜂蜜」  
  > 本次轮数：正好 5 轮对话。提问口吻：日常口语直问。

### 样例 2：数学换算与比较 + 缺条件拒算负样本（`C13`）
- **SYSTEM（固定前缀）**：
  > 你在写小学低中年级日常数学负样本问答（每条 2 题）：第 1 题为用户给出一个明显算错的式子或结果，AI 明确指出错在哪并分步算出正确答案；第 2 题为用户少给了关键条件（如缺单价、缺总数、缺单位），AI 必须直接说明缺少哪项条件、没法直接算，请对方补全后再算，绝不自己瞎假设数字硬算。严格输出 JSON：`{"items":[{"u":"...","a":"..."}]}`。
- **USER（Python 配方拼接）**：
  > 题型：两步乘减应用题与单位换算；涉及物品：「铅笔」「练习本」；数值由程序校验，必须写出中间计算步骤。

### 样例 3：600 字以内多维组合写故事（`SG-06`）
- **SYSTEM（固定前缀）**：
  > 你在写「4～6 维复杂复合约束写故事」对话。故事正文必须 100% 采用客观第三人称（仅人物对话引号内可出现“我”），严禁超过 600 字，严禁小明/小红等高频撞名。`u` 是真人自然口语提出的写故事要求（绝不照抄系统标签），`a` 是一篇 320～550 字完整故事，必须原样包含全部给定必含词并落实剧情、波折、结局与额外约束。严格输出 JSON：`{"items":[{"u":"...","a":"..."}]}`。
- **USER（Python 配方拼接）**：
  > - 人物与关系：罗听雨、许知夏（一对同班同学）  
  > - 时空背景：起大风的黄昏，在老小区车棚  
  > - 必含 2 个跨界物品：「拨浪鼓」「轮胎」  
  > - 剧情与波折：途中遇到「小动物受惊钻进角落不敢出来」  
  > - 结局走向：靠一个简单省力的日常土办法妥善收场  
  > - 额外约束：包含至少 2 句人物对话，文风轻松幽默

### 样例 4：写完故事后多轮反问 / 连续多轮改稿（`SG-13` / `SG-14`）
- **`SG-13`（写完故事 → 3～5 轮反问细节 + 未提拒编）**：
  > 第 1 轮按给定人物/地点/物品/波折写出 220～330 字第三人称小故事；第 2～N 轮由用户反过来追问 AI 刚写的故事细节（起因、关键物件、一句话概括），其中必含 1 轮故意追问故事里压根没写的细节（如主角几岁、物品多少钱、第二天去哪了），AI 必须忠实原文老实拒编。
- **`SG-14`（写完故事 → 3～4 轮连续叠改）**：
  > 第 1 轮写出 210～320 字初稿；第 2 轮用户提出第 1 条修改意见（换关键物品/改天气/加对话）；第 3 轮在第 2 版基础上继续叠加第 2 条意见（改结局/压短到 200 字）；第 4 轮再做开头微调或核对修改前后变化，要求每轮严格继承上一版设定、绝不回滚。
